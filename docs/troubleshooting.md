# 트러블슈팅 기록

실제로 제공된 오류와 후속 실행 결과를 바탕으로 정리했다. 각 항목에서 확인된 사실과 확정하지 못한 원인을 구분한다.

<a id="issue-01"></a>

## 사례 1. PowerShell에서 Git 명령을 인식하지 못함

### 1. 문제

**실행 명령**

```powershell
git --version
```

**실제 오류 핵심 부분**

```text
git : 'git' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다.
```

### 2. 원인 가설

Git이 설치되지 않았거나, 설치 경로가 PATH에 반영되지 않았을 수 있다고 판단했다. 이 오류만으로 두 원인 중 하나를 확정할 수는 없다.

### 3. 확인

오류는 명령 이름을 찾지 못하는 단계에서 발생했다. GitHub 인증이나 저장소 권한 점검 이전의 로컬 실행 환경 문제였다. 설치 절차를 진행한 뒤 제공된 설치 로그에서 Git 패키지 확인, 설치 관리자 해시 확인, 설치 성공을 확인했다.

```text
찾음 Git [Git.Git] 버전 2.56.0.4
설치 관리자 해시를 확인했습니다.
설치 성공
```

### 4. 해결

다음 명령을 사용하는 설치 절차를 안내받아 진행했다.

```powershell
winget install --id Git.Git -e --source winget
```

### 5. 재검증

**실행 명령**

```powershell
git --version
```

**실제 출력**

```text
git version 2.56.0.windows.4
```

명령이 정상적으로 실행됐다. 설치 후 터미널을 재시작했는지 여부는 기록에서 확정하지 않으며, 성공 판정은 실제 버전 응답을 근거로 한다.

### 6. 배운 점

설치 완료 메시지와 명령 실행 성공을 구분해야 한다. 명령 미인식 오류가 나면 설치 상태·경로 인식을 확인하고, 같은 명령을 재실행해 검증한다.

**관련 증거:** [1단계 Git 점검](01-environment.md#git)

## 사례 2. 디렉터리 경로를 실행 명령으로 입력함

### 1. 문제

폴더 이동 후 현재 경로 출력값을 다시 입력했다.

```bash
/home/user/mission-step2
```

**실제 오류**

```text
-bash: /home/user/mission-step2: Is a directory
```

### 2. 원인 가설

경로를 단독으로 입력해 Bash가 해당 경로를 실행하려 했지만, 실행 파일이 아닌 디렉터리이기 때문에 실패한 것으로 판단했다.

### 3. 확인

디렉터리 생성 직후 제공된 확인 결과는 다음과 같다.

```text
drwxr-xr-x 2 user user 4096 Nov  7 03:04 mission-step2
```

맨 앞의 d가 디렉터리임을 나타낸다. 오류 이전에 수행한 위치 확인 결과와 이후 경로 비교 실습의 위치 확인 결과도 실습 디렉터리였다.

```text
/home/user/mission-step2
```

### 4. 해결

이미 원하는 위치에 있었으므로 디렉터리를 다시 만들거나 복구할 필요가 없었다. 출력된 경로와 입력할 명령을 구분하고, 같은 위치에서 다음 실습을 진행했다.

### 5. 이후 정상 동작 확인

**실제로 후속 수행한 명령**

```bash
touch empty.txt
ls -l empty.txt
```

**실제 출력**

```text
-rw-r--r-- 1 user user 0 Nov  7 03:09 empty.txt
```

파일 생성과 후속 파일 조작이 정상적으로 수행됐다.

### 6. 배운 점

출력된 경로는 명령이 아니다. 디렉터리 이동에는 cd, 현재 위치 확인에는 pwd, 파일 읽기에는 cat 등 목적에 맞는 명령을 사용한다.

**관련 증거:** [2단계 오류 및 후속 결과](02-terminal-paths.md#troubleshooting)

## 추가 사례 3. Windows에서 클라우드 Linux 경로를 사용함

### 1. 문제

**PowerShell 입력**

```powershell
cd /workspace/developer-workspace
```

**실제 오류 핵심 부분**

```text
cd : 'C:\workspace\developer-workspace' 경로는 존재하지 않으므로 찾을 수 없습니다.
```

### 2. 원인 가설 및 확인

클라우드 Linux의 작업 경로를 Windows PowerShell에서 사용했다. 오류에 표시된 경로는 Windows의 C 드라이브 경로였으며, 로컬 WSL 실습에서 실제 확인된 홈 경로는 /home/user였다. 서로 다른 환경의 경로를 혼동한 것이 원인이다.

### 3. 해결·대안

Linux 실습은 WSL2 Ubuntu에 들어가 홈 디렉터리 아래에 전용 폴더를 만들어 진행하는 방법을 사용했다. 저장소 작업은 실제로 내려받은 로컬 저장소 경로에서 수행해야 한다.

### 4. 확인 범위

이후 Ubuntu에서 아래 실습 경로를 실제 확인하고 파일 조작을 완료했다.

```text
/home/user/mission-step2
/home/user/mission-step3
```

원래 실패했던 Windows 경로로 다시 이동해 성공한 기록이나 로컬 저장소 clone 성공 기록은 아직 제공되지 않았다. 따라서 이 사례는 환경 구분과 실습 대안의 성공까지만 보고한다.

### 5. 배운 점

명령을 실행하기 전에 Windows PowerShell인지 Ubuntu인지 확인하고, 예시 경로가 자신의 환경에 실제 존재하는지 확인한다.

## 전체 정리

| 사례 | 문제 유형 | 확인된 결과 |
|---|---|---|
| 1 | 명령 설치·경로 인식 | Git 버전 조회 정상화 |
| 2 | 명령과 출력값 혼동 | 올바른 위치에서 후속 실습 정상 수행 |
| 3 | 실행 환경과 경로 혼동 | 로컬 Ubuntu 실습 경로에서 작업 성공; 원래 Windows 저장소 경로 해결은 미검증 |

사례 1과 2는 문제·가설·확인·해결·후속 검증을 실제 기록으로 연결했다. 사례 3은 추가 학습 사례로, 확인하지 못한 부분을 명시했다.
