## 3. 실습 대상 생성

**PowerShell에서 실행**

```powershell
wsl -d Ubuntu
```

Ubuntu 진입 직후 프롬프트의 현재 위치는 `/mnt/c/Users/user`였다. 홈 디렉터리로 이동한 뒤 전용 실습 디렉터리를 생성했다.

**Ubuntu에서 실행**

```bash
cd ~
mkdir mission-step3
cd mission-step3
pwd
```

**pwd 실제 출력**

```text
/home/user/mission-step3
```

**파일·디렉터리 생성 명령**

```bash
touch permission-file.txt
mkdir permission-dir
```

두 생성 명령은 별도 출력이 없었으며 다음 조회에서 존재를 확인했다.

<a id="before"></a>

## 4. 변경 전 권한

**실행 명령**

```bash
ls -ld permission-file.txt permission-dir
```

**실제 출력**

```text
drwxr-xr-x 2 user user 4096 Nov  7 07:58 permission-dir
-rw-r--r-- 1 user user    0 Nov  7 07:57 permission-file.txt
```

**해석**

- 파일: `-rw-r--r--` → 일반 파일, 권한 `644`
- 디렉터리: `drwxr-xr-x` → 디렉터리, 권한 `755`
- 소유자와 그룹은 모두 `user`이다.
- 파일 크기 0바이트로, 실습용 빈 파일임을 확인했다.

처음부터 최종 목표와 같은 권한이었다. 따라서 같은 값을 다시 적용하는 것만으로 끝내지 않고, 먼저 `600`·`700`으로 바꾼 뒤 `644`·`755`로 변경하여 실제 변화를 남겼다.

<a id="restricted"></a>

## 5. 첫 번째 변경 — 파일 600, 디렉터리 700

**실행 명령**

```bash
chmod 600 permission-file.txt
chmod 700 permission-dir
ls -ld permission-file.txt permission-dir
```

**실제 조회 출력**

```text
drwx------ 2 user user 4096 Nov  7 07:58 permission-dir
-rw------- 1 user user    0 Nov  7 07:57 permission-file.txt
```

**해석**

| 대상 | 숫자 | 문자 권한 | 의미 |
|---|---|---|---|
| 파일 | `600` | `rw-------` | 소유자만 읽기·쓰기 |
| 디렉터리 | `700` | `rwx------` | 소유자만 목록 읽기·내부 항목 관리·접근 |

그룹과 기타 사용자의 권한이 제거된 것을 문자 권한으로 확인했다.

<a id="file-final"></a>

## 6. 파일을 먼저 644로 변경한 중간 상태

**실행 명령**

```bash
chmod 644 permission-file.txt
ls -ld permission-file.txt permission-dir
```

**실제 출력**

```text
drwx------ 2 user user 4096 Nov  7 07:58 permission-dir
-rw-r--r-- 1 user user    0 Nov  7 07:57 permission-file.txt
```

파일은 `644`로 변경됐고, 아직 변경하지 않은 디렉터리는 `700`이었다. 이 시점은 파일 변경만 완료된 중간 상태이다.

<a id="final"></a>

## 7. 디렉터리를 755로 변경한 최종 상태

**실행 명령**

```bash
chmod 755 permission-dir
ls -ld permission-file.txt permission-dir
```

**실제 출력**

```text
drwxr-xr-x 2 user user 4096 Nov  7 07:58 permission-dir
-rw-r--r-- 1 user user    0 Nov  7 07:57 permission-file.txt
```

파일은 `644`, 디렉터리는 `755`로 최종 확인됐다.

<a id="comparison"></a>

## 8. 전체 변경 전후 비교

| 대상 | 최초 | 첫 번째 변경 | 파일만 재변경한 중간 상태 | 최종 |
|---|---|---|---|---|
| 파일 | `644` | `600` | `644` | `644` |
| 디렉터리 | `755` | `700` | `700` | `755` |

| 대상 | 최초 문자 권한 | 제한 후 문자 권한 | 최종 문자 권한 |
|---|---|---|---|
| 파일 | `-rw-r--r--` | `-rw-------` | `-rw-r--r--` |
| 디렉터리 | `drwxr-xr-x` | `drwx------` | `drwxr-xr-x` |

최초와 최종 값은 같지만, 중간 출력으로 실제 권한이 변경됐다가 다시 변경된 것을 확인할 수 있다. 권한 변경 명령의 성공 여부는 후속 `ls -ld` 결과로 판정했다.

<a id="concepts"></a>

## 9. 권한 표시와 숫자 해석

### 9-1. ls 출력의 맨 앞 10글자

```text
- rw- r-- r--
│ │   │   └─ 기타 사용자 권한
│ │   └───── 그룹 권한
│ └───────── 소유자 권한
└─────────── 종류: -는 일반 파일, d는 디렉터리
```

위 표시는 실제 권한 문자열을 설명하기 위해 띄어 쓴 구조도이다. 첫 글자는 파일 종류이고, 뒤의 9글자는 세 글자씩 소유자·그룹·기타 사용자 권한을 나타낸다.

| 대상 | 의미 |
|---|---|
| 소유자 | 파일이나 디렉터리를 소유한 사용자 |
| 그룹 | 소유자가 아닌 사용자 중 해당 그룹에 속한 사용자 |
| 기타 사용자 | 소유자도 아니고 해당 그룹에도 속하지 않는 사용자 |

기본적인 권한 판정은 사용자에게 해당하는 부류를 적용한다. 세 부류의 권한을 모두 더해서 사용하는 것은 아니다.

### 9-2. 숫자 계산

| 권한 | 숫자 |
|---|---:|
| 읽기 `r` | 4 |
| 쓰기 `w` | 2 |
| 실행·접근 `x` | 1 |
| 권한 없음 `-` | 0 |

각 자리에서 필요한 권한 값을 더한다. 숫자 세 자리의 순서는 소유자 → 그룹 → 기타 사용자이다.

```text
600 = 6 / 0 / 0 = rw- / --- / ---
700 = 7 / 0 / 0 = rwx / --- / ---

644 = 6 / 4 / 4 = rw- / r-- / r--
      소유자: 4+2 = 읽기·쓰기
      그룹:   4   = 읽기
      기타:   4   = 읽기

755 = 7 / 5 / 5 = rwx / r-x / r-x
      소유자: 4+2+1 = 읽기·쓰기·접근
      그룹:   4+1   = 읽기·접근
      기타:   4+1   = 읽기·접근
```

여기서 `755`의 의미는 이번 실습 대상인 디렉터리를 기준으로 설명했다. 일반 파일의 `x`는 실행 권한이다.

<a id="file-directory"></a>

## 10. 일반 파일과 디렉터리의 차이

| 구분 | 일반 파일 | 디렉터리 |
|---|---|---|
| 역할 | 글·사진·프로그램 등의 내용 저장 | 파일·하위 디렉터리의 이름과 항목 관리 |
| 이번 실습 대상 | `permission-file.txt` | `permission-dir` |
| 비유 | 서류 한 장 | 서류철 |
| r | 파일 내용 읽기 | 내부 항목 이름 목록 읽기 |
| w | 파일 내용 수정 | 내부 항목 생성·삭제·이름 변경에 관여 |
| x | 프로그램·스크립트 실행 | 디렉터리 접근·통과 |

디렉터리 안에서 항목을 생성·삭제하려면 보통 디렉터리의 `w`와 `x`가 함께 필요하다. 디렉터리 목록의 이름을 읽는 것과 그 안의 파일 내용을 읽는 것은 다르다. 파일 내용을 읽으려면 경로상의 디렉터리 접근 권한과 파일 자체의 읽기 권한 등도 필요하다.

파일 삭제는 파일 자체의 쓰기 권한만으로 결정되지 않는다. 다른 제한이 없다면 부모 디렉터리의 쓰기·접근 권한이 중요하다. 실제 시스템에서는 ACL, sticky bit, 읽기 전용 파일시스템 등 추가 제한이 있을 수 있다.

## 11. 검증 범위와 학습 결과

이번 실습에서는 소유자인 `user`로 `chmod`를 실행하고, `ls -ld`의 표시로 권한 변경을 검증했다. 다른 사용자 계정으로 로그인해 접근 거부를 시험한 기록은 없으므로 그런 실험에 성공했다고 주장하지 않는다.

파일 `644`와 디렉터리 `755`의 의미를 해석하고, 파일의 실행 권한과 디렉터리의 접근 권한이 다르다는 점을 정리했다. 최초와 최종 값이 같더라도 중간 변경 기록을 남겨야 실제 변경 실험을 증명할 수 있음을 확인했다.

이 권한값은 실습용 대상에 적용한 값이다. 비밀 설정 파일 등 모든 파일에 동일한 공개 범위를 적용해야 한다는 의미는 아니다.
