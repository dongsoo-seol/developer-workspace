# 2단계 실습 보고서 — 터미널 조작 및 절대·상대 경로

## 1. 실습 개요

Ubuntu 터미널에서 디렉터리와 파일을 직접 생성·조회·복사·이동·이름 변경·삭제하고, 같은 파일을 절대 경로와 상대 경로로 읽었다. 작업 위치를 바꾼 뒤 다시 파일을 읽어, 경로를 해석하는 기준이 어떻게 달라지는지 확인했다.

이 문서는 학습자가 로컬 PC의 WSL2 Ubuntu에서 실행하여 제공한 실제 터미널 기록을 바탕으로 작성했다. 가독성을 위해 사용자명·컴퓨터명이 포함된 프롬프트는 제거하고 명령과 출력을 구분했다. 발췌한 출력은 해당 위치에 표시했다. 출력이 없는 명령은 후속 조회 결과로 검증했다.

| 항목 | 내용 |
|---|---|
| 실습일 | 2026-11-07, 한국 표준시(KST) |
| 호스트 OS | Microsoft Windows 10 Pro, 10.0.19045 |
| 터미널·작업 창 | Windows PowerShell에서 WSL2 Ubuntu 실행 |
| Linux 배포판 | Ubuntu 26.04.1 LTS |
| Linux 기본 쉘 | Bash — `/bin/bash` |
| 사용자 홈 디렉터리 | `/home/user` |
| 실습 디렉터리 | `/home/user/mission-step2` |
| 기록 마지막의 현재 위치 | `/home/user` |

Windows·Ubuntu·쉘 정보는 앞서 수행한 1단계 확인 결과를 사용했다. 아래 수행 기록은 2단계에서 실제 실행한 명령과 출력이다.

## 2. 학습 목표

- 현재 작업 디렉터리와 숨김 파일을 포함한 목록을 확인한다.
- 디렉터리와 빈 파일, 내용이 있는 파일을 생성한다.
- 파일을 복사·이동·이름 변경·삭제하고 결과를 검증한다.
- 절대 경로와 상대 경로로 같은 파일을 조회한다.
- 현재 위치가 바뀔 때 상대 경로가 달라지는 이유를 설명한다.
- `.`, `..`, `~`의 의미를 설명한다.

## 4. 상세 실행 기록

<a id="log-01"></a>

### 4-1. 현재 위치 및 숨김 파일 확인

**목적:** 파일 조작 전에 현재 위치와 주변 파일·디렉터리를 확인한다.

**실행 명령**

```bash
pwd
```

**실제 출력**

```text
/home/user
```

**실행 명령**

```bash
ls -la
```

**실제 출력 중 일부 발췌**

아래는 홈 디렉터리의 원본 목록에서 현재·상위 디렉터리와 숨김 파일 예시를 발췌한 것이다. 실습과 무관한 개인 설정 경로 등은 생략했다. 파일명·권한·크기·시각은 제공된 출력의 값이다.

```text
drwxr-x--- 9 user user 4096 Nov  4 22:23 .
drwxr-xr-x 3 root root 4096 Nov  4 07:16 ..
-rw-r--r-- 1 user user 3771 Nov  4 07:16 .bashrc
-rw-r--r-- 1 user user  807 Nov  4 07:16 .profile
```

**결과 해석:** 현재 위치는 `/home/user`였다. `ls`의 `-l` 옵션으로 자세한 정보를, `-a` 옵션으로 이름이 점으로 시작하는 숨김 항목까지 확인했다.

<a id="log-02"></a>

### 4-2. 실습 디렉터리 생성과 이동

**목적:** 실습 파일을 보관할 전용 디렉터리를 생성하고 그 안으로 이동한다.

**실행 명령**

```bash
mkdir mission-step2
ls -ld mission-step2
```

**실제 출력**

`mkdir`는 별도 출력이 없었고, 후속 `ls -ld`의 출력은 다음과 같다.

```text
drwxr-xr-x 2 user user 4096 Nov  7 03:04 mission-step2
```

**실행 명령**

```bash
cd mission-step2
pwd
```

**실제 출력**

`cd`는 별도 출력이 없었고, 후속 `pwd`의 출력은 다음과 같다.

```text
/home/user/mission-step2
```

**결과 해석:** 디렉터리가 생성됐고 현재 위치도 그 안으로 변경됐다. `ls -ld`의 `-d`는 디렉터리 내부가 아니라 디렉터리 자체의 정보를 확인하는 옵션이다.

<a id="log-03"></a>

### 4-3. 빈 파일 생성

**목적:** 내용이 없는 파일을 생성하고 크기를 확인한다.

**실행 명령**

```bash
touch empty.txt
ls -l empty.txt
```

**실제 출력**

`touch`는 별도 출력이 없었고, 후속 `ls -l`의 출력은 다음과 같다.

```text
-rw-r--r-- 1 user user 0 Nov  7 03:09 empty.txt
```

**결과 해석:** `empty.txt`가 생성됐고 파일 크기는 0바이트였다. `touch`는 대상 파일이 없으면 빈 파일을 만든다. 이미 있는 파일에 사용하면 내용을 지우는 대신 시간 정보를 갱신한다.

<a id="log-04"></a>

### 4-4. 숨김 파일 생성 및 조회

**목적:** 점으로 시작하는 파일을 만들고 숨김 파일 포함 조회를 확인한다.

**실행 명령**

```bash
touch .hidden-example
ls -la
```

**실제 출력**

```text
total 8
drwxr-xr-x  2 user user 4096 Nov  7 03:11 .
drwxr-x--- 10 user user 4096 Nov  7 03:04 ..
-rw-r--r--  1 user user    0 Nov  7 03:11 .hidden-example
-rw-r--r--  1 user user    0 Nov  7 03:09 empty.txt
```

**결과 해석:** `.hidden-example`과 `empty.txt`가 모두 표시됐다. 점으로 시작하는 파일도 일반 파일이며, 기본 `ls` 출력에서 숨겨지는 관례가 적용된다. 숨김 이름 자체가 접근을 막는 보안 기능은 아니다.

<a id="log-05"></a>

### 4-5. 내용이 있는 파일 생성 및 읽기

**목적:** 문자열을 파일에 저장하고 실제 내용을 읽는다.

**실행 명령**

```bash
printf '터미널 실습 기록입니다.\n절대 경로와 상대 경로를 연습합니다.\n' > notes.txt
cat notes.txt
```

**실제 출력**

파일 작성 명령은 별도 출력이 없었고, `cat`의 출력은 다음과 같다.

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**결과 해석:** `printf`의 출력이 `>`에 의해 `notes.txt`로 저장됐다. `\n`은 줄바꿈을 나타낸다. `cat`으로 두 줄이 저장된 것을 확인했다. `>`는 기존 파일에 사용하면 내용을 덮어쓰므로 대상 파일을 확인해야 한다.

<a id="log-06"></a>

### 4-6. 파일 복사

**목적:** 원본을 유지하면서 별도의 복사본을 만든다.

**실행 명령**

```bash
cp notes.txt notes-copy.txt
ls -l notes.txt notes-copy.txt
```

**실제 출력**

```text
-rw-r--r-- 1 user user 85 Nov  7 03:17 notes-copy.txt
-rw-r--r-- 1 user user 85 Nov  7 03:13 notes.txt
```

**실행 명령**

```bash
cat notes-copy.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**결과 해석:** 원본과 복사본이 모두 존재했고 크기는 각각 85바이트였다. 복사본에서 원본과 같은 두 줄을 확인했다. 바이트 수는 글자 수와 같지 않을 수 있다.

<a id="log-07"></a>

### 4-7. 파일 이동

**목적:** 복사본을 하위 디렉터리로 옮기고 이동 전 위치와 목적지를 확인한다.

**실행 명령**

```bash
mkdir backup
mv notes-copy.txt backup/
ls -la
```

**실제 출력**

```text
total 16
drwxr-xr-x  3 user user 4096 Nov  7 03:19 .
drwxr-x--- 10 user user 4096 Nov  7 03:04 ..
-rw-r--r--  1 user user    0 Nov  7 03:11 .hidden-example
drwxr-xr-x  2 user user 4096 Nov  7 03:19 backup
-rw-r--r--  1 user user    0 Nov  7 03:09 empty.txt
-rw-r--r--  1 user user   85 Nov  7 03:13 notes.txt
```

**실행 명령**

```bash
ls -la backup
```

**실제 출력**

```text
total 12
drwxr-xr-x 2 user user 4096 Nov  7 03:19 .
drwxr-xr-x 3 user user 4096 Nov  7 03:19 ..
-rw-r--r-- 1 user user   85 Nov  7 03:17 notes-copy.txt
```

**결과 해석:** `notes-copy.txt`가 현재 디렉터리 목록에서 사라지고 `backup` 안에 나타났다. `cp`는 별도의 복사본을 만들고, `mv`는 파일의 위치 또는 이름을 변경한다.

<a id="log-08"></a>

### 4-8. 파일 이름 변경

**목적:** 같은 디렉터리 안에서 파일 이름만 바꾸고 내용을 확인한다.

**실행 명령**

```bash
mv backup/notes-copy.txt backup/renamed-notes.txt
ls -la backup
```

**실제 출력**

```text
total 12
drwxr-xr-x 2 user user 4096 Nov  7 03:21 .
drwxr-xr-x 3 user user 4096 Nov  7 03:19 ..
-rw-r--r-- 1 user user   85 Nov  7 03:17 renamed-notes.txt
```

**실행 명령**

```bash
cat backup/renamed-notes.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**결과 해석:** 파일 이름이 `renamed-notes.txt`로 변경됐으며 내용은 유지됐다. `mv`의 원본과 목적지가 같은 디렉터리에 있으면 이름 변경에 사용할 수 있다.

<a id="log-09"></a>

### 4-9. 파일 삭제

**목적:** 실습에서 만든 복사본을 삭제하고 결과를 확인한다. 삭제 전 파일의 존재는 바로 앞 4-8의 목록과 내용 확인 결과에 기록돼 있다.

**실행 명령**

```bash
rm backup/renamed-notes.txt
ls -la backup
```

**실제 출력**

```text
total 8
drwxr-xr-x 2 user user 4096 Nov  7 03:22 .
drwxr-xr-x 3 user user 4096 Nov  7 03:19 ..
```

**결과 해석:** 대상 파일이 목록에서 사라졌고 현재·상위 디렉터리를 뜻하는 `.`과 `..`만 남았다. 따라서 `backup` 내부의 실습 파일이 삭제됐음을 확인했다. 일반적인 `rm` 사용은 휴지통을 거치지 않으므로 경로를 확인해야 한다.

<a id="log-10"></a>

### 4-10. 절대 경로와 상대 경로로 같은 파일 조회

**목적:** 현재 위치에서 같은 파일을 두 방식으로 읽는다.

**실행 명령**

```bash
pwd
```

**실제 출력**

```text
/home/user/mission-step2
```

**절대 경로 조회 명령**

```bash
cat /home/user/mission-step2/notes.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**상대 경로 조회 명령**

```bash
cat ./notes.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**결과 해석:** `/`에서 시작하는 절대 경로와 현재 디렉터리를 기준으로 한 상대 경로가 같은 파일을 가리켰다. 두 명령에서 동일한 내용이 출력됐다.

<a id="log-11"></a>

### 4-11. 현재 위치 변경 후 같은 파일 조회

**목적:** 현재 위치를 바꾸면 상대 경로가 달라지는지 확인한다.

**실행 명령**

```bash
cd ..
pwd
```

**실제 출력**

```text
/home/user
```

**변경된 위치에서 상대 경로 조회**

```bash
cat mission-step2/notes.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**같은 절대 경로로 조회**

```bash
cat /home/user/mission-step2/notes.txt
```

**실제 출력**

```text
터미널 실습 기록입니다.
절대 경로와 상대 경로를 연습합니다.
```

**결과 해석:** 현재 위치가 홈 디렉터리로 바뀌자 상대 경로는 `./notes.txt`에서 `mission-step2/notes.txt`로 달라졌다. 같은 파일의 절대 경로는 변하지 않았으며, 파일 내용도 동일했다.

## 5. 경로 개념 및 명령어 정리

### 5-1. 절대 경로와 상대 경로

| 구분 | 의미 | 이번 실습의 예시 |
|---|---|---|
| 절대 경로 | 최상위 디렉터리 `/`부터 나타낸 경로 | `/home/user/mission-step2/notes.txt` |
| 상대 경로 | 현재 작업 디렉터리를 기준으로 나타낸 경로 | `./notes.txt`, `mission-step2/notes.txt` |

같은 파일을 읽었을 때의 비교는 다음과 같다.

| 현재 작업 위치 | 사용한 상대 경로 | 사용한 절대 경로 |
|---|---|---|
| `/home/user/mission-step2` | `./notes.txt` | `/home/user/mission-step2/notes.txt` |
| `/home/user` | `mission-step2/notes.txt` | `/home/user/mission-step2/notes.txt` |

상대 경로는 현재 위치에 의존한다. 따라서 명령을 실행하기 전에 `pwd`로 현재 위치를 확인하는 것이 중요하다. 같은 파일의 위치가 바뀌지 않았다면 절대 경로는 현재 작업 위치가 바뀌어도 그대로 사용할 수 있다.

### 5-2. `.`, `..`, `~`의 의미

| 기호 | 의미 | 실습과의 연결 |
|---|---|---|
| `.` | 현재 디렉터리 | `./notes.txt`로 현재 디렉터리의 파일을 읽음 |
| `..` | 상위 디렉터리 | `cd ..`로 실습 디렉터리에서 홈 디렉터리로 이동 |
| `~` | 현재 사용자의 홈 디렉터리로 확장되는 쉘 표기 | 이번 환경의 홈 경로는 `/home/user` |

`~`는 실제 디렉터리 이름이 아니라 Bash가 홈 경로로 바꾸는 표기이다. 예를 들어 `cd ~`는 홈 디렉터리로 이동하는 명령이다. 이 예시는 개념 설명이며, 위 상세 로그에 별도 실행 결과가 추가된 것은 아니다.

### 5-3. 사용 명령어 요약

| 명령 | 역할 | 이번 실습에서 확인한 내용 |
|---|---|---|
| `pwd` | 현재 작업 위치 출력 | 홈·실습 디렉터리 확인 |
| `ls -la` | 숨김 항목 포함 상세 목록 | 숨김 파일·이동·삭제 결과 확인 |
| `ls -ld` | 디렉터리 자체 정보 확인 | 실습 디렉터리 생성 확인 |
| `cd` | 현재 작업 디렉터리 변경 | 실습 폴더 진입, 상위 폴더 이동 |
| `mkdir` | 디렉터리 생성 | `mission-step2`, `backup` 생성 |
| `touch` | 파일 생성 또는 시간 갱신 | 빈 파일과 숨김 파일 생성 |
| `printf` | 지정 형식으로 문자열 출력 | `>`와 함께 내용 저장 |
| `cat` | 파일 내용 출력 | 원본·복사본·경로별 내용 확인 |
| `cp` | 복사 | 원본을 유지하고 복사본 생성 |
| `mv` | 이동 또는 이름 변경 | 복사본 이동 후 이름 변경 |
| `rm` | 파일 삭제 | 실습용 복사본 삭제 |

## 6. 트러블슈팅 — 디렉터리 경로를 명령처럼 입력한 오류

### 문제

실습 디렉터리로 이동한 뒤 `pwd`에 나온 경로를 다시 명령처럼 입력했다.

**입력한 내용**

```bash
/home/user/mission-step2
```

**실제 오류 출력**

```text
-bash: /home/user/mission-step2: Is a directory
```

### 원인 가설

디렉터리 주소를 단독으로 입력하여 Bash가 해당 경로를 실행 대상으로 해석한 것으로 추정했다.

### 확인

앞서 실행한 `ls -ld mission-step2`의 출력은 `d`로 시작해 디렉터리임을 보여준다. 또한 오류 메시지 자체가 대상이 디렉터리임을 나타낸다. 이후의 `pwd` 기록에서도 현재 위치가 `/home/user/mission-step2`임을 확인할 수 있었다.

즉, 디렉터리 생성이나 이동이 실패한 것이 아니라, 이미 출력된 경로를 다시 실행 명령으로 입력한 것이 문제였다.

### 해결 및 이후 확인

이미 올바른 위치에 있었으므로 별도 복구 작업 없이 다음 실습을 진행했다. 이후 `touch empty.txt`와 `ls -l empty.txt`가 성공했고, 파일 생성·복사·이동·경로 조회도 정상적으로 수행됐다.

### 재발 방지

- 터미널에 입력할 **명령**과 화면에 표시된 **출력**을 구분한다.
- 경로는 명령의 인수로 사용한다. 디렉터리 이동에는 `cd`, 파일 조회에는 `cat`을 사용한다.
- `pwd`로 나온 경로 자체를 다시 명령으로 입력하지 않는다.

이 문서에는 실제 발생한 트러블슈팅 1건을 기록했다. 전체 과제의 2건 이상 조건은 1단계에서 기록한 Git 명령 인식 문제 등과 함께 정리해야 한다.

## 7. 실습 결과물과 검증 요약

### 7-1. 실행 기록 기준 파일 구성

아래는 생성·이동·삭제 기록을 바탕으로 정리한 구조도이며, 별도로 실행한 `tree` 명령의 출력은 아니다.

```text
/home/user/mission-step2/
├── .hidden-example       # 생성한 숨김 빈 파일
├── empty.txt             # 생성한 일반 빈 파일
├── notes.txt             # 실습 문구 두 줄이 저장된 원본
└── backup/               # 복사본 이동·이름 변경·삭제 후 비어 있음
```

임시 복사본의 처리 흐름은 다음과 같다.

```text
notes.txt
  └─ 복사 → notes-copy.txt
               └─ 이동 → backup/notes-copy.txt
                            └─ 이름 변경 → backup/renamed-notes.txt
                                               └─ 삭제
```

## 8. 학습 결과

이번 실습으로 터미널에서 파일과 디렉터리를 조작하고, 출력이 없는 명령도 후속 조회로 검증하는 방법을 익혔다. 복사·이동·이름 변경·삭제를 실제 파일의 위치와 내용으로 구분했다.

또한 절대 경로는 최상위 디렉터리에서 시작하고, 상대 경로는 현재 작업 위치를 기준으로 해석된다는 점을 동일 파일 조회 결과로 확인했다. 이후 실습에서도 `pwd`로 위치를 확인하고, 조작 후 `ls`와 `cat`으로 결과를 확인하는 방식을 사용할 수 있다.
